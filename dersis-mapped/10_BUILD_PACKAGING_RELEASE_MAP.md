# 10 — Build, Packaging, and Release Map

> **Captured 2026-06-04.** _Updated 2026-06-08: reflects the packaging fixes in `build_embed.bat` and `installer.iss` — the `python*._pth` now also appends `..` (app dir) for safe-path mode, a bundled-interpreter import smoke test was added, the `Dersis.exe` wrapper is now a GUI-subsystem app, and `installer.iss` requires Inno Setup ≥ 6.3.0._

## 1. Version source of truth

The file `VERSION` at the repo root holds a single line such as `1.0.0`. This is the **only** authoritative version string. It is read by:

- `scheduler_app/_version.py::_read_version()` (runtime, multi-location fallback).
- `build_embed.bat` (Windows shell `set /p APP_VERSION=<VERSION`).
- `build_nuitka.bat` (same shell trick).
- `.github/workflows/release.yml` (extracts the version from the pushed `vX.Y.Z` tag and verifies it matches `VERSION`).
- `installer.iss` (includes `build\version.iss` generated by the build script).

All three build paths validate that `VERSION` looks like `X.Y.Z` (digits) before continuing.

## 2. Build methods

The repository supports **two Windows packaging paths** (both produce `build\Dersis.dist\` and feed the same Inno Setup script):

### 2.1 Embeddable Python (recommended — `build_embed.bat`)

Speed: ~2 min. Complexity: low.

1. Validate `VERSION` format.
2. Clean `build\` directory.
3. Download the embeddable-Python zip for the chosen Python version (3.11.9).
4. Extract into `build\Dersis.dist\python\`.
5. **Configure the embeddable Python search path** by editing `python<ver>._pth`: uncomment `import site` (so pip-installed site-packages are importable) **and append `..`** — the dist root, one level up — so the bundled `scheduler_app` package is importable. **Why `..` is required:** when a `._pth` file is present the interpreter runs in *safe-path* mode and does **not** add the launched script's own directory to `sys.path`; without the `..` line, `import scheduler_app` fails and the app closes silently under `pythonw.exe` (`ModuleNotFoundError: No module named 'scheduler_app'`).
6. Vendored `get-pip.py` bootstraps pip inside the embeddable runtime.
7. `pip install -r requirements-lock.txt` into the embeddable runtime.
8. Copy the application source into `build\Dersis.dist\`:
   - `scheduler_gui.py`, `VERSION`, `scheduler_app/` package, `flags/`, `docs/dersis.png`, license, etc.
9. Compile the package to `.pyc` (and remove the `.py` sources from `scheduler_app`, keeping `scheduler_gui.py`).
10. Generate the launchers in `build\Dersis.dist\`: `Dersis.vbs`, `Dersis.bat`, and `Dersis.exe`. `Dersis.exe` is a tiny C# wrapper compiled with `Add-Type … -OutputType WindowsApplication` (a **GUI-subsystem** app, previously `ConsoleApplication`) so launching it does **not** flash a console window before handing off to `pythonw.exe`.
11. **Verify the build**, including an **import smoke test**: run the bundled interpreter exactly as the launcher will (`"%PY_DIR%\python.exe" -c "from scheduler_app.app import SchedulerApp"`) and fail the build if it cannot import the app package. This catches `python*._pth`/`sys.path` regressions at build time instead of as a silent crash on the user's PC.
12. Write `build\version.iss` containing `#define AppVersion "X.Y.Z"` and print a summary.

The result is a self-contained directory: drop it anywhere, run the launcher.

### 2.2 Nuitka compilation (`build_nuitka.bat`)

Speed: 5–15 min. Complexity: high.

1. Validate `VERSION`.
2. `pip install -r requirements-build.txt` (adds nuitka, ordered-set, Pillow).
3. `python verify_deps.py` — abort if any dep is missing (Nuitka can't auto-discover hidden imports).
4. Compile with Nuitka in **standalone directory mode**:
   - `--standalone --enable-plugin=pyqt6 --include-data-dir=...flags/=flags --include-data-dir=...docs/=docs --include-data-file=...VERSION=VERSION --include-package=ortools --windows-icon-from-ico=...app_icon.ico --output-dir=build`
5. Write `build\version.iss`.
6. Sanity-check that `build\Dersis.dist\Dersis.exe` exists.

Nuitka produces a smaller distribution and hides the source code as compiled binaries, but it is finicky about dependency discovery — hence the explicit `verify_deps.py` gate.

### 2.3 Inno Setup installer (`installer.iss`)

Run with `iscc installer.iss` after either build path. Highlights:

- **Minimum-version guard** (near the top of the script): `#if VER < EncodeVer(6,3,0)` → `#error ...` → `#endif`, requiring **Inno Setup 6.3.0+**. The script uses the `x64compatible` architecture identifier, which was introduced in 6.3.0; the guard fails the compile early with a clear message instead of a confusing "invalid [Setup] value" error on older compilers.
- Defines: `AppName`, `AppFullName`, `AppVersion` (from `build\version.iss`), `AppPublisher`, `AppCopyright`, `AppURL`. Offline build: `AppURL` is now an empty string (`""`) — the former remote URL was removed.
- `Source: "build\Dersis.dist\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs`.
- Generates Start Menu and (optionally) Desktop shortcuts to the launcher.
- Embeds `installer\LICENSE.txt` as the license shown to users.
- Wizard images (`wizard_image.bmp`, `wizard_small_image.bmp`) from `installer/`.
- Output: `Output\Dersis_Setup.exe`.

## 3. Dependency files

| File | Purpose | When pip-installed |
|------|---------|--------------------|
| `requirements.txt` | Direct runtime deps, minimum versions. | Local dev (`pip install -r requirements.txt`). |
| `requirements-build.txt` | Includes `requirements.txt` + nuitka, Pillow, ordered-set. | Building the installer. |
| `requirements-dev.txt` | Includes `requirements.txt` + pytest. | Local dev convenience. |
| `requirements-lock.txt` | Pinned exact versions (e.g. PyQt6==6.11.0, ortools==9.15.6755). | CI/CD reproducible installs, embeddable-Python builds. |

The runtime deps are `PyQt6`, `cryptography`, `openpyxl`, `pandas`, `reportlab`, `ortools`, `packaging`, and `deepdiff`. The HTTP `requests` library was **removed** along with the auth/licensing/update subsystem — nothing in the offline app makes a network call. The lock file lists both direct **and** transitive dependencies so Nuitka can statically discover everything.

## 4. CI/CD pipelines (`.github/workflows/`)

### 4.1 `ci.yml`

Triggers: push or PR on `master`.
Purpose: lightweight validation — fails fast. **There are no automated test files**, so CI does not run pytest; it performs static/structural checks only:

- Set up Python 3.11; `pip install -r requirements.txt` + `pip check`.
- **Version checks**: `VERSION` exists and is valid semver; `scheduler_app._version.__version__` matches `VERSION`; on a `v*` tag push, the tag matches `VERSION`.
- **Build-file checks**: required files (`build_embed.bat`, `installer.iss`, `verify_deps.py`, `scheduler_gui.py`) exist.
- **Import smoke test**: imports a handful of core modules (`scheduler_app._version`, `core.models`, `core.workflow`, `plans`, `storage`) and fails if any raise.
- **Installer reference check**: `installer.iss` points at `build\Dersis.dist` and uses the `Dersis_Setup_v{#AppVersion}` output name.

### 4.2 `build-installer.yml`

Triggers: callable workflow + dispatch.
Runs on Windows. Builds the installer via the requested method (`embed` default or `nuitka`), then uploads `Dersis_Setup.exe` and its `.sha256` as workflow artefacts.

### 4.3 `release.yml`

Triggers:
- Push of a tag matching `v*` (e.g. `v1.0.0`).
- Manual `workflow_dispatch`.

Steps:
1. Verify `VERSION` content matches the tag.
2. Call `build-installer.yml` (workflow_call).
3. Create / update a GitHub Release with the installer + checksum + auto-generated release notes.

### 4.4 `claude.yml` and `claude-code-review.yml`

Hooks for the Claude Code GitHub app. Not part of the release pipeline. They listen for PR comments/reviews/issue mentions and dispatch the Claude Code action.

## 5. Auto-update (removed)

The offline build has **no in-app update mechanism**. The former auto-updater (`scheduler_app/auth/updater.py`, the `desktop-update.php` manifest fetch, `UpdateDialog`, staged download + silent install, and the `update_prefs` skip/defer state) was deleted in the offline conversion. To ship a new version, build a fresh installer and distribute it; the app never checks for or downloads updates.

## 6. Risks and fragile areas in the release process

| Risk | Location | Notes |
|------|----------|-------|
| `VERSION` and Git tag drift | `release.yml` does verify this, but a manual `iscc installer.iss` without re-running the build script will use the stale `build\version.iss`. | Always re-run `build_embed.bat` before `iscc`. |
| Embeddable Python URL hardcoded | `build_embed.bat` | If the embeddable-Python download URL changes shape, the build breaks. |
| Nuitka hidden-import discovery | `verify_deps.py` is the safety net. | If a new transitive dep appears, it must be added to `verify_deps.py` and `requirements-lock.txt` before the next Nuitka build. |
| Inno Setup license file path | `installer.iss` references `installer\LICENSE.txt`. | Renaming it silently breaks the installer. |
| Wizard BMPs are binary | `wizard_image.bmp` / `wizard_small_image.bmp`. | Regenerate via `installer/create_wizard_images.py` if the logo changes. |
| GitHub Release secrets | `release.yml` needs `secrets.GITHUB_TOKEN` (default) plus possibly a code-signing secret. | Verify before re-running. |
| Crash log is **plain text** | `storage.crash_log_path` | This is intentional (recoverability) — do not encrypt it. |
| Embeddable-Python `python<ver>._pth` edit | `build_embed.bat` | Must both uncomment `import site` **and** append `..` (the app dir) — safe-path mode otherwise drops the script dir from `sys.path` and `import scheduler_app` fails silently under `pythonw.exe`. The build's import smoke test (`python.exe -c "from scheduler_app.app import SchedulerApp"`) now guards this regression; if Python release notes change the `._pth` format, the PowerShell edit and the smoke test must be kept in sync. |
