# 00 — Exclusions

Files and directories that were deliberately *not* mapped in detail, with the reason.

## Directories never inspected

| Path | Reason |
|------|--------|
| `.git/` | Internal Git metadata. Standard, opaque, not part of the application. |
| `__pycache__/` (any) | Compiled bytecode, regenerated automatically. |
| `.pytest_cache/` (if any) | Pytest cache, regenerated automatically. |
| `build/`, `dist/`, `*.dist/`, `*.egg-info/`, `Output/` (if any) | Build outputs. The .gitignore explicitly excludes these. |
| `.venv/`, `.eggs/`, `.tools/` (if any) | Virtual environments and editor tools. |
| `archive_repo_cleanup/` | Repository preserves legacy / removed files for recovery only. Not part of the active application. Documented as a group in `12_RISKS_TECH_DEBT_AND_UNKNOWN.md`. |
| `mnt/` | Mounted external content unrelated to the application source. (Present at the time of mapping; treated as out of scope.) |

## Files documented only as a group (not individually)

| Path pattern | Reason |
|--------------|--------|
| `flags/*.png` (22 files) | Binary PNG flag icons. Documented as one group in `file-maps/flags__group.md`. |
| `scheduler_app/assets/*.{ico,png}` (8 files) | Binary application icons at various resolutions. Documented in `file-maps/scheduler_app__assets.md`. |
| `installer/wizard_image.bmp`, `installer/wizard_small_image.bmp` | Binary BMPs generated by `create_wizard_images.py`. Generation script is mapped; the BMPs themselves are output artefacts. |
| `docs/dersis.png` | Binary brand image; source artefact, no executable content. |

## Why the very large file is mapped at block level

| File | Lines | Approach |
|------|-------|----------|
| `scheduler_app/ui/translations.py` | 21,790 | Mapped as a single structured block: a 22-language dict of translation keys plus a `tr()`/`set_language()`/`is_rtl()` API at the bottom. Per-key documentation would be redundant — the keys are descriptive. The file map enumerates the languages, the key naming conventions, and the line ranges of each language block. |
| `scheduler_app/ui/app.py` | 5,130 | Mapped at the level of major method groups (menus, file ops, drag-drop, optimization handlers, …) instead of every line — line-by-line for 5k lines would obscure rather than clarify. |
| `scheduler_app/ui/dialogs.py` | 4,451 | Same approach as `app.py`: mapped per dialog class. |
| `scheduler_app/core/schedule_optimizer.py` | 1,044 | Mapped per major method (`_greedy_construct`, LNS loop, multi-start, CP-SAT bridge). |
| `scheduler_app/core/constraint_negotiator.py` | 1,342 | Mapped per analyser/suggester/builder class. |
| `scheduler_app/core/logic.py` | 1,456 | Mapped per function group (occupancy maps, scoring, backtracking, AI bridge). |
| `scheduler_app/ui/renderer.py` | 1,414 | Mapped per QGraphicsItem subclass and scene assembly. |

All other files (under 1000 lines) are mapped at a finer granularity — typically per function/class with a function-level table.

## What is NOT excluded but treated cautiously

- Test files **are** mapped. They are small and high-value for understanding what behaviour is considered guaranteed.
- CI workflows **are** mapped. They define the release contract.
- The legacy back-compat shims in `scheduler_app/__init__.py` **are** mapped — they encode an important architectural invariant (old flat imports still work).
